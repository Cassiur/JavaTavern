# 核心功能取舍

## 产品定位

JavaTavern 不是 AiChat 的 Java 重写，也不追求短期复制其全部功能。定位是：**原生 Android、可审计 Agent、移动端性能可量化的本地优先 AI 角色助手**。

## 必须具备

| 能力 | 选择 | JavaTavern 的实现方向 |
| --- | --- | --- |
| 私聊与角色 | 保留 | 原生 RecyclerView、分角色本地历史、角色配置 |
| 流式输出与停止 | 保留 | OpenAI-compatible SSE、50 ms 合并刷新、生命周期取消 |
| 连续上下文 | 保留 | 最近消息窗口，后续增加 token 预算与摘要 |
| Agent | 已有首个写工具 | `/clear` 确认卡片、事务执行、结果和审计；下一步工具注册表 |
| 卡片渲染 | 已有原生状态卡 | 普通卡、提案卡、结果卡；下一步拆多 ViewType schema |
| 图片输入 | 已实现 | Photo Picker、后台压缩、私有存储、LRU、视觉模型协议 |
| 角色卡导入 | JSON 已实现 | SillyTavern V2 JSON 已落库；PNG 元数据待做 |
| 世界书 | 基础已实现 | 关键词/常驻条目按会话触发，4000 字符预算 |
| 记忆 | 保留但简化 | 会话摘要 + 用户确认的长期记忆，不自动无限写入 |
| 搜索 | 会话内已实现 | SQLite FTS、结果列表和上下文定位；跨会话待做 |
| 数据导入导出 | 保留 | ZIP manifest、版本校验、冲突预览和原子替换 |
| 性能与稳定性 | 强化 | Macrobenchmark、分页、内存、耗电、弱网、vivo 真机 |

## 第二优先级

| 能力 | 原因 |
| --- | --- |
| 群聊与 @ 提及 | 能展示 Agent 调度，但复杂度高于私聊 |
| 每会话模型与预设 | 对多 Provider 有价值，需先稳定配置模型 |
| 消息重新生成与分支 | 酒馆体验核心，但需先设计消息版本 schema |
| Prompt 请求诊断 | 对求职差异化很强，可展示上下文和 token 组成 |
| 深浅色与壁纸 | 必要体验项，但不优先于协议和稳定性 |

## 暂缓或删除

| 能力 | 决策理由 |
| --- | --- |
| 朋友圈动态 | 与 vivo AI 助手 JD 关系弱，容易把项目做散 |
| 贴图生成与切割 | 偏产品扩展，不是当前核心能力 |
| 完整创意写作模式 | 可由会话预设覆盖，暂不单独建立复杂模块 |
| 桌面双栏版 | 当前目标是 Android，不引入跨端负担 |
| 世界书节点连线编辑器 | UI 成本过高，先做可解释的规则列表 |
| 多家图片生成服务 | 先完成图片输入与视觉理解，再考虑生图 |

## 防止“看起来抄袭”的约束

1. 不使用 AiChat 的名称、女仆设定、页面结构、图标、文案和资源。
2. Agent 采用“提案—确认—执行—审计”四阶段，而不是复制其 Agent Center。
3. 卡片使用 Android 原生 ViewType 和版本化 schema，不移植 HTML/CSS。
4. 记忆默认需要用户确认，突出可控与隐私，而不是完全自动写入。
5. 性能报告、生命周期处理、Keystore 和真机适配作为项目主要差异点。

## 开发顺序

1. **协议底座**：上下文窗口、流式节流、取消、错误恢复。
2. **Agent 闭环**：首个写工具已完成，继续抽象工具注册与参数 schema。
3. **角色能力**：JSON 角色卡和基础世界书已完成，继续 PNG 与编辑页。
4. **多模态**：单图选择、压缩、视觉消息已完成，继续多图与错误降级。
5. **本地能力**：分页和会话 FTS 已完成，继续导入导出与摘要记忆。
6. **性能证据**：实现层优化已完成第一轮，继续 Macrobenchmark、内存与耗电报告。
