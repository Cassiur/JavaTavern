# 专题 11：分页、搜索与长列表

## 首屏与上拉

聊天页不再调用全量 `loadMessages`。首屏取最近 60 条，用户滚到顶部附近后以第一条持久化消息 ID 为游标，加载更早 40 条。

插入旧消息后使用 `scrollToPositionWithOffset` 恢复原锚点，避免列表突然跳动。

## RecyclerView 更新

- 整批替换使用 DiffUtil 比较数据库 ID 和可见内容。
- 加载历史使用 `notifyItemRangeInserted`。
- 流式消息只更新最后一项。
- 图片异步回调会检查 ViewHolder 当前绑定路径，防止复用后显示错图。

## 搜索与定位

SQLite v5 建立 FTS4 表和同步触发器。用户搜索后只展示最多 30 个结果，点击其中一条再查询前后各 20 条并定位目标，而不是把整个会话加载进内存。

## 仍需测试

实现正确不等于规模已验证。必须生成 1000/10000 条数据，测量：首屏 SQL、Cursor 构造、DiffUtil、图片缓存、上拉分页、搜索 P95 和滚动掉帧。

## 口述题

比较 `LIMIT 40 OFFSET 10000` 与 `WHERE id < cursorId LIMIT 40` 的执行代价和功能限制。
