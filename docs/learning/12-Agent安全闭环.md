# 专题 12：Agent 安全闭环

## 威胁模型

模型输出、角色卡、用户消息和远端服务都可能是不可信输入。任何一方都不能通过一句自然语言直接获得“删数据、改配置、代发消息”的权限。

## JavaTavern 的最小闭环

1. 路由器只返回本地已注册的 action type。
2. 写操作生成随机 action token 和 PENDING 提案。
3. UI 只对 PENDING 提案显示确认/取消。
4. 用户确认后再进入数据库执行器。
5. 清空和成功结果在同一事务提交。
6. 审计表记录 PENDING/CANCELLED/CONFIRMED/SUCCEEDED/FAILED。
7. 未知 action 默认失败，不通过反射兜底执行。

## 为什么审计表独立

如果审计记录和聊天消息一起被 `/clear` 删除，就无法回答“谁在什么时候授权了什么操作”。独立表保留最小责任链，同时不保存 API Key 等敏感值。

## 下一步设计

定义统一 `AgentTool<P, R>`：工具名、版本、JSON 参数 schema、风险等级、超时、幂等键、执行器和结果渲染器。高风险工具还要二次确认或系统生物识别。
