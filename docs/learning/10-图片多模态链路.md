# 专题 10：图片多模态链路

## 完整链路

```text
Photo Picker URI
  -> 后台校验输入大小
  -> ImageDecoder/BitmapFactory 解码
  -> 最长边 1600 px
  -> JPEG 85% 写入 files/message_images
  -> 预览与消息落库(path + MIME)
  -> 列表采样解码 + LRU
  -> 网络线程转 data:image/jpeg;base64
  -> OpenAI-compatible image_url content
```

## 为什么不长期保存 Picker URI

URI 权限可能是临时的，设备重启或进程重建后直接读取可能失败。项目把压缩副本复制到应用私有目录，数据库只记录内部绝对路径和 MIME。

## 为什么不把 Base64 存数据库

Base64 体积约增加三分之一；放入 SQLite 会让分页 Cursor、备份和查询都变重。项目只在网络线程构造请求时编码，消息库保存路径。

## 内存控制

- 解码前检查文件大小。
- API 28+ 通过 ImageDecoder 直接设置目标尺寸。
- 老版本先读 bounds 再设置 `inSampleSize`。
- 列表显示再按目标边采样，并以有限 LRU 缓存。
- 移除未发送附件和清空会话时删除私有图片。

## 当前边界

只支持单图，统一输出 JPEG，未保留透明通道，也没有多图、相机、上传 URL 或 Provider 能力探测。
