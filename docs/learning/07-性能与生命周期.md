# 专题 07：性能与生命周期

## 已采用的手段

- Application 到首帧埋点和 `reportFullyDrawn()`。
- 网络、数据库、图片处理分别在后台执行器。
- SSE delta 每 50 ms 合并刷新。
- 首屏 60 条、向上每页 40 条键集分页。
- DiffUtil 和 `notifyItemRangeInserted`，避免无条件全表重绑。
- 图片最长边 1600 px、列表采样解码、内存 LRU 缓存。
- 页面销毁取消网络、关闭线程池和图片加载器。
- 主题绘制统一窗口背景，移除 Activity 根布局同色过绘制。

## 当前基线

API 36 模拟器中，一张测试图从约 169 KB PNG 转为约 64 KB JPEG；聊天页一次进程 PSS 约 64 MB。这只能说明测量入口可用，不代表所有设备和长会话都达到目标。

## 为什么不能夸大

一次数据受模拟器状态、磁盘缓存、JIT、后台进程和构建类型影响。正确报告至少需要：同一设备、相同版本、冷/温/热分类、多轮样本、中位数/P90、修改前后对照。

## 下一步实验

1. 冷启动 10 次并记录中位数/P90。
2. 生成 1000 和 10000 条消息，记录首屏耗时、上滑加载和 PSS。
3. 连续流式 2 分钟，检查主线程、GC 和 RecyclerView 帧。
4. 多张 12 MP 图片连续选择，检查峰值内存和 OOM。
5. 前后台切换、旋转、弱网和主动取消各重复 20 次。
6. vivo 真机检查系统栏、键盘、Photo Picker、后台限制和耗电。

## 生命周期债务

`ChatActivity` 仍保存流、分页、搜索和附件状态；旋转会取消生成。目标是：

```text
Activity/View
   -> ChatViewModel + SavedStateHandle
       -> ChatRepository
           -> LocalDataSource
           -> ModelProvider
           -> MediaStore
```

## 口述题

为什么“用了 LRU 缓存”不等于“内存优化完成”？回答中必须包含缓存上限、对象生命周期、命中率和测量。
