# 专题 02：消息发送链路

## 主链路

```text
点击发送
  -> ChatActivity.sendMessage
  -> UI 插入用户消息
  -> 数据库异步写入
  -> LocalAgentRouter
  -> 读取 ModelSettings
  -> ConversationWindow
  -> OpenAiCompatibleClient / MockReplyEngine
  -> MessageAdapter 更新
  -> 最终回复落库
```

## 需要理解

- 为什么 UI 和数据库写入可以先后并行。
- 为什么 Agent 路由在模型请求之前。
- 为什么上下文过滤 Agent 卡片。
- 为什么错误占位不直接写入数据库。

## 实践

新增一个离线回复规则：用户输入少于 4 个字时，要求其补充主语和目标。为规则补一个测试或手工验证记录。

## 追问

如果数据库写入失败，但 UI 已经显示消息，应该如何反馈和重试？
