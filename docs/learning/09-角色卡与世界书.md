# 专题 09：角色卡与世界书

## 导入流程

1. `OpenDocument` 只选择 JSON/文本文件。
2. 后台读取，大小上限 2 MB。
3. `CharacterCardParser` 同时兼容 V2 `data` 包装和直接字段。
4. 校验 `name`，整理 description/personality/scenario/system_prompt。
5. SHA-256 作为来源哈希，角色和世界书在同一事务落库。
6. 重新加载角色列表，点击后按 ID 查询完整世界书。

示例文件位于 `samples/character-card-v2.json`。

## 世界书激活

`WorldBookPromptBuilder` 扫描最近 12 条文本：

- `constant=true` 且 enabled 的条目始终进入。
- 普通条目只要任一关键词命中就进入。
- 总内容不超过 4000 字符，防止世界书无限占用上下文。

当前是字符预算，不是 token 预算；对中英文和不同模型并不精确。下一步要增加优先级、位置、递归深度和模型 tokenizer。

## 安全边界

角色卡内容本质是不可信 Prompt。它可以影响模型回答，但不能获得 Android 方法调用权限。导入文件大小、字段、事务和重复策略都由本地代码控制。

## 实践

复制示例角色卡，增加一个关键词条目，导入后解释它在哪一轮被激活、为什么不会每轮都注入。
