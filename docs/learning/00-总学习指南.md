# JavaTavern 总学习指南

## 1. 这份文档怎么用

这不是一份让你从头背到尾的教程，而是 JavaTavern 的学习地图。每一章都遵循同一闭环：

1. 先说出你对问题的理解。
2. 沿真实代码找到入口和出口。
3. 修改一个最小功能并运行。
4. 回答本章追问。
5. 把结果写进开发记录。

判断是否掌握不看“看了多久”，只看三个证据：能脱稿解释、能定位代码、能独立修改。

## 4. 一条消息经历什么

### 4.1 输入阶段

用户点击发送后，`ChatActivity` 读取并清空输入框，立刻把用户消息加入 RecyclerView，同时把数据库写入任务提交给单线程执行器。

这里体现两个原则：

- UI 先响应，避免等待数据库造成卡顿。
- SQLite 写入不在主线程执行。

### 4.2 Agent 路由阶段

输入先交给 `LocalAgentRouter`。`/plan` 和 `/status` 直接生成只读卡片；`/clear` 生成 `AGENT_PROPOSAL`，只有用户点击确认才会执行。清空和结果卡落库位于同一事务，状态另写 `agent_audit`。

当前缺的是把单个命令抽象为通用工具注册表、参数 schema 和风险等级，而不是再证明“按钮能点”。

### 4.3 模型配置阶段

普通输入读取 `SecureModelSettingsStore`：

- Base URL 和模型名保存在 SharedPreferences。
- API Key 使用 Android Keystore 中的 AES 密钥加密后保存。
- 没有配置模型时使用离线 `MockReplyEngine`，保证项目可演示。

### 4.4 上下文构建阶段

`ConversationWindow` 从当前消息中反向选择最近 20 条文本或图片消息，过滤 Agent 卡片。`WorldBookPromptBuilder` 扫描最近 12 条文本，加入常驻条目和命中关键词的条目，总量限制为 4000 字符。

20 条只是临时限制，不是最终 token 策略。正确演进方向是：

1. 计算不同模型的 token 预算。
2. 保留最近高价值消息。
3. 更早历史使用摘要。
4. 世界书和记忆按优先级注入。
5. 把最终 Prompt 组成展示给用户诊断。

### 4.5 网络与流式阶段

`OpenAiCompatibleClient` 在网络线程执行：

1. 构造 `/chat/completions` 地址。
2. 写入 system/user/assistant 消息。
3. 设置 `stream=true`。
4. 读取 SSE 行。
5. 把 `data:` 交给 `SseEventParser`。
6. 收到 `[DONE]` 后结束。

网络线程不能直接修改 View。delta 进入线程安全缓冲区，每 50 ms 合并一次并切到主线程更新最后一条消息。

### 4.6 取消与落库阶段

用户点击停止时由 `ChatViewModel` 结束当前会话；正常完成或主动停止后才保存最终文本，异常终态不应把错误占位写入历史。Activity 因配置变化销毁时不直接取消 ViewModel 会话；真正离开页面并触发 `onCleared()` 后再统一取消和释放资源。

## 5. 必学 Android 知识

### 5.1 Activity 生命周期

需要掌握：`onCreate`、`onStart`、`onResume`、`onPause`、`onStop`、`onDestroy`。

流式会话现在由 `ChatViewModel` 持有；配置变化不会由 Activity 直接取消生成，Activity 重建后重新观察快照。仍需通过真机或模拟器验证占位消息不重复、最终数据库行 ID 正确回填；SavedStateHandle 仍是后续增强项。

### 5.2 主线程与后台线程

- View 只能在主线程修改。
- 网络和数据库不能阻塞主线程。
- `Handler(Looper.getMainLooper())` 用于切回主线程。
- `ExecutorService` 用于执行数据库和网络任务。
- 取消、关闭和回调顺序必须避免页面销毁后的更新。

### 5.3 RecyclerView

需要掌握 Adapter、ViewHolder、布局复用、ViewType、局部刷新、DiffUtil、分页。

当前 Agent 卡片和文本消息在同一 item 中切换可见性。功能可用，但随着卡片类型增加，应改为多个 ViewType 和独立 ViewHolder。

### 5.4 SQLite

需要掌握表、索引、事务、Cursor、schema version 和 migration。

当前数据层使用统一 `TavernDatabase`，并把旧角色库和消息库迁入新库。迁移失败必须回滚并保留旧文件，不能为了启动成功静默丢弃聊天记录。

### 5.5 Android Keystore

Keystore 保护的是加密密钥不被普通方式导出。它不能阻止：

- 应用进程已被攻破时读取正在使用的明文。
- 用户主动把 Key 输入到恶意应用。
- 截屏之外的物理观察。

所以还需要 HTTPS、日志脱敏、备份限制和最小暴露时间。

## 6. AI 客户端必学知识

### 6.1 SSE

SSE 是服务器持续发送文本事件的协议。OpenAI-compatible 常见形式：

```text
data: {"choices":[{"delta":{"content":"你"}}]}
data: {"choices":[{"delta":{"content":"好"}}]}
data: [DONE]
```

必须处理：空行、非 `data:` 行、usage-only 事件、畸形 JSON、网络中断、用户取消和无文本返回。

### 6.2 Provider 适配

OpenAI-compatible、Gemini 和 Anthropic 的 URL、认证、请求体和事件格式不同。正确设计是定义 `ModelProvider` 接口，每家 Provider 独立实现，Activity 不应出现大量 provider 判断。

### 6.3 Prompt 组成

一个成熟请求至少可能包含：

- 系统指令。
- 角色设定。
- 世界书命中条目。
- 长期记忆。
- 会话摘要。
- 最近历史。
- 用户当前输入。
- 图片或其他多模态内容。
- 工具定义与执行结果。

### 6.4 Agent 安全

“让模型直接调用客户端函数”风险很高。JavaTavern 的目标链路是：

```text
自然语言
  -> Agent 提案
  -> schema 校验
  -> 确认卡片
  -> 用户确认
  -> 工具执行
  -> 结果卡片
  -> 审计日志
```

删除、修改配置、代发消息、导入覆盖等写操作必须确认。只读查询可以根据风险等级免确认。

## 7. 性能学习路线

### 7.1 启动

当前同时记录：

- `am start -W` 的系统视角启动时间。
- Application 到首帧的内部埋点。
- `reportFullyDrawn()`。

单次数字不是优化结论。至少需要多轮冷启动、温启动和热启动，使用中位数或分位数比较修改前后。

### 7.2 消息列表

长会话风险：

- 一次加载全部记录导致内存增长。
- 富文本和图片重复解码。
- token 逐个刷新造成布局抖动。
- 滚动位置和键盘变化触发过多布局。

当前已实现 50 ms 合并刷新、最近 60 条首屏、每页 40 条键集分页、DiffUtil、采样解码和 LRU 图片缓存。下一步是 1000/10000 条自动化数据与 Macrobenchmark，不要把“采用了优化手段”说成“已经证明更快”。

### 7.3 内存与耗电

需要检查：Activity 泄漏、未关闭 Cursor、未取消请求、线程池生命周期、Bitmap、后台任务和重试风暴。

耗电优化不是“少写几行代码”，而是减少唤醒、网络请求、CPU 重算和后台持续运行。

## 11. 学习顺序

建议顺序：

1. 项目运行与目录。
2. 消息发送完整链路。
3. SSE 与请求取消。
4. Agent 与结构化卡片。
5. SQLite 与 migration。
6. Keystore 与隐私。
7. 生命周期与性能。
8. 角色卡与世界书。
9. 图片多模态链路。
10. 分页、FTS 与长列表。
11. Agent 安全闭环。

每完成一个专题，要在语音中用 60 秒解释，再做一次代码修改。只阅读不算完成。
